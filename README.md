# 아파트 매물 크롤링 파이프라인

특정 아파트 단지의 현재 매물(매매/전세/월세)을 네오넷·텐컴즈·한방에서 자동으로 긁어와
중복 제거하고 정리해서 보여주는 스크립트.

## 사용법

```bash
cd /work/djchoi/Claude_ground/realestate

# 이미 캐시된 단지 (목동 11/12/13단지) - 바로 실행
python3 pipeline.py "목동신시가지13단지"

# 처음 보는 단지 - region_cd(법정동코드) 없이 실행하면 네오넷 검색으로 자동 resolve됨
python3 pipeline.py "목동신시가지9단지"

# 다른 지역이라 자동 resolve가 안 되면 법정동코드 직접 지정
python3 pipeline.py "아무단지" --region 4111310300

# 한방 호출 생략 (더 빠름, 교차검증 skip)
python3 pipeline.py "목동신시가지13단지" --no-hanbang

# 원본 데이터까지 JSON으로 저장
python3 pipeline.py "목동신시가지13단지" --json out.json
```

출력은 매매/전세/월세로 나뉘고, 각 그룹 안에서 평형 큰 순으로 정렬됩니다.
동일한 물건이 여러 날 재확인(refresh)된 건 최신 날짜 기준으로 하나만 남깁니다
(네오넷/텐컴즈 각각 내부적으로만 중복제거 — 두 소스 간에 같은 매물이 겹쳐 보이는 건
정상이고, 오히려 교차검증 역할을 합니다).

### 빌라/다세대/원룸/상가 등 (단지명이 없는 매물) — `--region-only` 모드

아파트는 "목동13단지"처럼 이름으로 찾지만, 빌라·다세대는 그런 단지 개념이 없어서
지역(법정동) 단위로 통째로 긁어야 합니다. 이 모드는 텐컴즈만 지원합니다.

```bash
# 방배동(내방역 인근 포함) 빌라/다세대 - "빌라"가 아니라 "주택" 카테고리로 나온다
python3 pipeline.py --region-only --region 1165010100 --type 주택

# 원룸도 가능 (유효 --type 값: 아파트/오피스텔/분양권/주택/토지/원룸/상가/사무실/공장/재개발/건물)
python3 pipeline.py --region-only --region 1165010100 --type 원룸
```

**주의**: 텐컴즈 지역 필터는 아파트만큼 엄격하지 않습니다 — `--region` 코드를 잘못
입력해도 에러 없이 전국 매물이 섞여서 조용히 반환됩니다 (조용한 실패라 특히 위험).
반드시 정확한 10자리 법정동코드를 써야 하고, 결과가 그 동네와 무관해 보이면 코드부터
의심할 것. 정확한 코드는 감으로 짜맞추지 말고 정부 법정동코드표에서 직접 찾을 것
(방법은 `pipeline.py` 상단 docstring 참고 — PublicDataReader 깃허브에 있는
`code_bdong.json`을 받아서 grep하는 방식).

또한 "빌라"라는 이름의 카테고리는 존재하지 않는다 — 다세대/연립주택은 텐컴즈에서
**"주택"**으로 분류된다 (`TENCOMZ_TYPES` 참고). "빌라"로 검색하면 지역필터가
씹히면서 전국 매물이 섞여 나오는데, 이것도 에러가 안 나서 눈치채기 쉽지 않다.

법정동 자체가 넓어서(예: 방배동은 서래마을~내방역까지 다 포함) 지역코드만으로는
"역세권 도보 5분" 같은 정밀 필터링이 안 된다는 점도 감안할 것 — 매물명/비고에
역 이름이 직접 언급된 것들 위주로 걸러보는 게 최선이다.

## 네이버 공유링크 ID 디코딩 (`decode_naver_links.py`) — 수동 검증용, 자동조회 아님

네이버부동산 자체는 매물 상세 API가 강하게 봇 차단돼 있어서(쿠키/Referer를 다 갖춰도
`429 TOO_MANY_REQUESTS`) 자동 대량조회는 불가능합니다. 이 스크립트는 그 대신,
**사용자가 네이버에서 발견한 특정 매물의 공유링크**를 디코딩해서 `complexId`/
`articleId`/평형타입번호만 뽑아줍니다 (가격·평형·동/층은 여전히 화면에서 직접
읽어서 알려줘야 함 — 자동 조회 아님).

```bash
pip install --break-system-packages --user lzstring   # 최초 1회만

python3 decode_naver_links.py "https://naver.me/xxxxx" "https://naver.me/yyyyy"
python3 decode_naver_links.py --file links.txt   # 한 줄에 링크 하나씩
```

원리: 링크의 `layer` 쿼리파라미터가 lz-string 압축 포맷(알파벳이 `A-Za-z0-9+-`뿐,
`/` 없음, 패딩 없음 — 이게 식별 포인트)이라 `lzstring` 패키지로 바로 풀립니다.
풀어보면 `complexId`가 나오는데, 지금까지 확인한 모든 사례에서 이 숫자가 네오넷의
`complex_cd`·텐컴즈의 `aptNo`·한방의 `CD`와 정확히 일치했습니다 — 교차검증용으로
바로 쓸 수 있습니다.

## 오피스텔/상가 기준시가 조회 (`officetel_price.py`) — 매물망과 완전히 별개, 정부 공식 데이터

지금까지의 네오넷/텐컴즈/한방은 전부 "현재 호가(매물)"이고, 이건 **국세청이 매년
고시하는 세법상 평가액(기준시가)**입니다. 완전히 다른 데이터 종류라 별도 스크립트로
분리했습니다.

```bash
pip install --break-system-packages --user (설치 불필요 - 표준 라이브러리만 사용)

# data.go.kr에서 발급받은 서비스키 필요 (아래 참고)
export NTS_OFFICETEL_KEY="발급받은_인증키"

python3 officetel_price.py --bjd 1153010100                    # 그 동 전체
python3 officetel_price.py --bjd 1153010100 --building-name 신도림팰러티움
```

**서비스키 발급(무료, 5분, 보통 즉시승인)**: data.go.kr 회원가입 → ["국세청_상업용건물
오피스텔 기준시가_20260101"](https://www.data.go.kr/data/3036455/fileData.do) 데이터셋
페이지에서 "활용신청" → 마이페이지에서 인증키 복사.

**⚠️ 결정적 한계 두 가지 (실사용으로 검증됨):**
1. **데이터가 2020년 고시분에서 멈춰있습니다.** 데이터셋 제목은 "20260101"이라
   최신처럼 보이지만, 실제 오픈API(Swagger)는 2005~2020년 스냅샷만 등록돼 있고
   2021년 이후분은 API로 변환이 안 됐습니다 — 파일은 갱신했는데 API 래퍼는 갱신
   안 한 정부 쪽 관리 누락으로 보입니다. **2026년 현재가는 이 API로 못 받습니다.**
2. **아파트/주상복합 주거용 유닛은 원천적으로 안 나옵니다.** 이건 세법상
   "오피스텔·상업용건물"만 다루는 기준시가 데이터셋이고, 아파트는 기준시가가 아니라
   별도의 "공동주택가격"으로 공시됩니다. 디큐브시티로 실제 검증해봤는데, A동/B동
   (아파트로 등록됨)은 신도림동 3307건 안에 단 1건도 없었고, 순수 오피스텔
   (신도림월드메르디앙오피스텔 등)과 아파트 단지 부속 상가만 잡혔습니다.

아파트/주상복합 주거용 유닛의 공시가격은 대신 아래 `apt_gongsi_price.py`를 쓸 것.

## 아파트 공동주택 공시가격 조회 (`apt_gongsi_price.py`) — realtyprice.kr 직접 호출, data.go.kr 키 불필요

`officetel_price.py`가 다루지 못하는 아파트/주상복합 주거용 유닛의 공시가격을
국토교통부 "부동산공시가격알리미"(realtyprice.kr) 사이트가 내부적으로 쓰는 JSON API를
직접 호출해서 가져옵니다. data.go.kr 키 발급이 필요 없고, 정부가 매년 4/30 확정
고시하는 실제 공동주택가격을 그대로 받아옵니다.

```bash
# 단지 내 전체 호실 목록만 보기 (평형/동호 이름 확인용)
python3 apt_gongsi_price.py --sido 서울특별시 --sgg 구로구 --eub 신도림동 --apt 디큐브시티

# 특정 호실의 연도별(가능한 전체 이력) 공시가격
python3 apt_gongsi_price.py --sido 서울특별시 --sgg 구로구 --eub 신도림동 --apt 디큐브시티 \
    --dong-name A --ho-name 2202
```

**넘어야 했던 진짜 장애물은 NetFunnel(kwait.reb.or.kr) 접속 대기열이었습니다** — 정부
사이트 특유의 트래픽 제어 게이트로, 브라우저 JS가 자동 처리하지만 curl/requests로는
그냥 막힌 것처럼 보입니다(`/notice/town/siteLink.htm`가 계속 메인 페이지로 되돌아감).
실제로는 `kwait.reb.or.kr/ts.wseq?opcode=5101&...`을 호출해 `"5002:200:key=..."` 형태의
raw 응답을 받고, 그 문자열을 JS `escape()` 인코딩 그대로 `NetFunnel_ID` 쿠키에 실어
보내기만 하면 게이트를 통과합니다(한산할 때는 대기 없이 즉시 통과 — `nwait=0`).
이 세션에서 30회 이상 연속 조회해도 캡챠 없이 통과했습니다. 스크립트 상단 docstring에
전체 프로토콜과 각 API 엔드포인트(`searchBjdTownYear.bjd`→`searchApt.search`(단지/동/호)
→`townPriceListPastYearMap.search`(가격))를 정리해뒀습니다.

**주의**: `notice_date_year` 파라미터는 날짜처럼 생겼지만 실제 공시일(예: 2026년 4/30
고시)이 아니라 내부 배치 코드(2026년분 = `"20260626"`)입니다 — 하드코딩하지 말고
`searchNoticeDate.search`로 매번 조회할 것(스크립트가 자동으로 함). 또한 동일 평형이라도
동/층에 따라 공시가격이 꽤 벌어집니다(디큐브시티 전용 84.96㎡ 확인 사례: 8.38억~9.49억,
재산세 1주택 특례 기준선인 9억을 사이에 두고 갈림) — 특정 호실을 모르면 단지 전체를
"얼마"라고 뭉뚱그리지 말 것.

**"동" 처리 두 갈래**: 디큐브시티처럼 동 구분 없이 "아파트" 한 그룹으로만 묶인 단지가
있고(호 이름 자체에 "A-4605"처럼 동 정보가 들어있음), 목동신시가지처럼 101~113동/
1301~1334동 등 실제 동이 별도 목록으로 분리된 단지가 있습니다. `--dong-name`을
먼저 동 목록에서 찾고, 없으면 호 이름 접두사로 필터링하는 순서로 처리합니다
(`main()`의 `multi_dong` 분기 참고) — 다동단지에서 이 구분 없이 무조건 `dongs[0]`를
쓰면 엉뚱한 동을 조회하게 되니 주의.

**단지명 검색 시 등록명이 줄여져 있을 수 있음**: "목동신시가지13단지"로 검색하면
0건이 나오지만, 실제 등록명은 "단지"가 빠진 "목동신시가지13"입니다. 반대로
"목동신시가지"처럼 짧게 검색하면 1~14단지가 전부 걸려서 여러 건이 나오는데, 이때
`--apt`로 준 문자열이 `COMMON_APT_NAME`과 정확히 일치하지 않으면 스크립트가 후보
목록을 보여주고 멈춥니다(예전엔 말없이 `apts[0]`를 골라 엉뚱한 단지로 조회될 위험이
있었음). 후보 목록에 나온 `COMMON_APT_NAME` 값을 그대로 `--apt`에 넣으면 됩니다.

**API 자체는 페이지당 최대 5000건, 서버사이드 필터(cond) 없음** — 그래서
`officetel_price.py`는 법정동코드로 찾을 때 이진탐색(전체 72만건 중 perPage=1 프로브
~20회)으로 시작 위치를 찾은 다음 perPage=5000으로 한번에 긁어옵니다
(`find_bjd_range`/`fetch_bjd` 참고). 데이터는 법정동코드 오름차순 정렬 확인됨.

## 소스 커버리지 요약

| 소스 | 강점 | 약점 |
|---|---|---|
| 네오넷 (m.neonet.co.kr) | 매매/월세 잘 잡힘 | 전세 거의 없음 |
| 텐컴즈 (nhp.ten.co.kr) | 전세 포함 가장 풍부, 대형평형까지 잡힘 | 첫 요청이 느림 (ASP.NET 페이지네이션) |
| 한방 (karhanbang.com) | 깔끔한 JSON, 중개사 연락처 포함 | 매물 수가 훨씬 적음 (보조 검증용) |

**막혀서 못 쓰는 것들**: 네이버부동산(전면 차단), 직방/KB부동산(SPA라 데이터 안 나옴),
부동산포스(공개 매물검색 자체가 없음 — 순수 중개사용 ERP + 네이버 직송 전용).
그래서 이 파이프라인도 네이버가 보여주는 전체 매물의 일부만 잡습니다 — 특히
포스로만 등록하고 네오넷/텐컴즈/한방 어디에도 안 올린 매물은 원천적으로 못 봅니다.

## 새 단지 추가하기

`pipeline.py` 상단의 `COMPLEX_CACHE` 딕셔너리에 단지명/region_cd/neonet_complex_cd/
tencomz_aptno를 추가해두면 다음부터 resolve 단계 없이 바로 실행됩니다. 스크립트가
자동으로 출력해주는 `[neonet] resolved region_cd=... complex_cd=...`,
`[tencomz] resolved aptNo=...` 로그를 그대로 복사해 넣으면 됩니다.

## 코드 구조 (`pipeline.py`)

- `neonet_resolve` / `neonet_fetch` — 네오넷 EUC-KR 페이지 파싱 (아파트 전용)
- `tencomz_resolve_aptno` / `tencomz_fetch` — 텐컴즈 단지 매물 (ASP.NET `__doPostBack` 페이지네이션 포함)
- `tencomz_fetch_region` — 텐컴즈 지역 단위 매물 (빌라/원룸/상가 등, `--region-only` 모드)
- `hanbang_fetch` — 한방 JSON API 호출 (아파트 전용)
- `dedupe_by_unit` — (동, 층, 거래유형, 가격) 기준 중복 제거
- `print_report` / `print_region_report` — 매매/전세/월세로 나눠 평형 큰 순으로 출력
